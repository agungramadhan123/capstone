Bertindaklah sebagai Senior AI Engineer dan Systems Architect. Saya sedang membangun sistem "Vehicle Tracking, Counting, and Analytics" siap produksi untuk Jalan Buah Batu, Bandung, menggunakan Ultralytics YOLOv8, ByteTrack, dan Roboflow Supervision.

Bantu saya menyusun seluruh arsitektur kode, skrip penunjang, dan metodologi pengujian secara berurutan berdasarkan 4 fase berikut. Berikan kode yang clean, modular, efisien, dan memiliki manajemen memori yang sangat ketat (anti-memory leak).

---

### FASE 1: CLEANING DATASET & RE-VALIDATION (HULU)
1. Buat skrip Python untuk mendeteksi dan menghapus kelas bias bernama "Labelling-data-laku-lintas" dari file konfigurasi `data.yaml`.
2. Skrip harus otomatis menyesuaikan jumlah kelas (nc) menjadi 4 kelas valid saja ('Bis', 'Mobil', 'Motor', 'Truk') tanpa merusak urutan indeks kelas lainnya.
3. Tulis skrip pendek untuk menjalankan validasi ulang (`model.val()`) menggunakan model 'best.pt' terakhir saya dan data.yaml yang baru dibersihkan untuk memperbarui nilai mAP@0.5 murni tanpa harus retrain dari awal.

### FASE 2: CORE MONITORING APPLICATION (PRODUKSI & DEMO)
Buat skrip utama `main.py` untuk pemrosesan video dengan arsitektur ketat "Antigraviti" (Fail-Safe) dan visualisasi tingkat tinggi untuk demo publik:

1. FAIL-SAFE INPUT HANDLING:
- Gunakan OpenCV VideoCapture. Sistem harus mencoba membaca Live RTSP Stream URL CCTV ATCS.
- Jika koneksi RTSP gagal atau terputus tengah jalan, tangkap exception tersebut dan secara otomatis (seamless) alihkan input ke file video lokal (.mp4) cadangan tanpa menghentikan program (anti-crash).

2. OPTIMAL TRACKING & OCCLUSION HANDLING:
- Integrasikan YOLOv8 (v8s atau v8m) dengan ByteTrack (`model.track(..., persist=True)`).
- Konfigurasikan pelacakan dua tahap (Two-Stage Matching): set `track_thresh=0.25` untuk deteksi utama, namun izinkan Kalman Filter melacak objek dengan confidence rendah (0.1 - 0.25) untuk mempertahankan ID sepeda motor yang saling berdempetan atau terhalang kendaraan lain (occlusion).
- Naikkan `track_buffer` ke 60/90 frame agar sistem tidak memberikan ID baru saat Angkot 05 mendadak berhenti/ngetem di pinggir jalan Buah Batu.
- Tambahkan logika displacement minimal (piksel): jika pusat objek tidak berpindah secara signifikan, kunci statusnya agar tidak memicu double-count saat terjadi macet total di atas garis.

3. DIRECTIONAL VIRTUAL LINE CROSSING:
- Manfaatkan `sv.LineZone` dan `sv.LineZoneAnnotator` dari Supervision.
- Buat garis horizontal satu arah (misal: hanya menghitung arus dari Selatan ke Utara).

4. ANTI-MEMORY LEAK REAL-TIME LOGGING:
- Buat class `TrafficLogger` untuk mencatat event kendaraan langsung ke file `traffic_logs_buahbatu.csv`.
- Gunakan modul `csv` bawaan Python dengan mode append (`'a'`). Jangan simpan data di dalam Pandas DataFrame selama loop video berjalan untuk mencegah RAM membengkak.
- Struktur kolom CSV: `timestamp` (YYYY-MM-DD HH:MM:SS), `frame_id`, `vehicle_id`, `class_name`, `confidence`, `direction`.
- Secara berkala, bersihkan ID lama dari memori penampung lokal (`set`) jika ByteTrack sudah resmi menghapus ID tersebut dari buffer aktif.

5. VISUAL HUD & THE "WOW" FACTOR:
- Tampilkan bounding box yang bersih dengan trace ekor pergerakan (`sv.TraceAnnotator`).
- Tampilkan papan informasi (HUD) akumulasi total kendaraan per kelas di pojok kiri atas dengan background semi-transparan yang estetik.
- Efek Visual Garis: Ubah warna virtual line secara dinamis (Hijau secara default, dan berkedip Merah selama 2 frame saat ada kendaraan yang sah melintas, lalu kembali Hijau).

### FASE 3: VALIDASI LAPANGAN & EVALUASI JAM SIBUK (1 JAM)
Buat skrip analisis terpisah `evaluate_accuracy.py` untuk menguji performa sistem setelah merekam video 1 jam di jam sibuk Buah Batu:

1. AGREGASI INTERVAL TIME-SERIES:
- Baca file `traffic_logs_buahbatu.csv` hasil rekaman menggunakan Pandas.
- Lakukan resample data otomatis untuk mengelompokkan total hitungan kendaraan per interval 5 menit (total 12 blok data dalam 1 jam).

2. KALKULASI AKURASI & MAE:
- Sediakan dictionary/array untuk memasukkan data hitungan manual manusia (Ground Truth) per 5 menit sebagai pembanding.
- Hitung nilai Mean Absolute Error (MAE) per kelas kendaraan menggunakan rumus formal MAE.
- Tampilkan tabel komparasi akhir antara Hitungan Sistem vs Hitungan Manual beserta persentase akurasi akhir per kelas untuk laporan performa project.

Berikan seluruh implementasi kode di atas secara terstruktur, modular, dan siap dijalankan.
